Exhibit C · How it is built

From P6 update to leadership report

The dashboards are only as good as the schedule behind them. The pipeline checks the XER first, keeps every update as a snapshot, and calculates the measures in one model. Planners keep working in P6, and the report pack is ready when the update closes.

Extract

XER export from each P6 update, with baseline and data date captured automatically.

Validate

Integrity checks before anything is reported: open ends, hard constraints, out-of-sequence progress, actuals after data date, missing logic.

Snapshot

Each update stored as a snapshot, so trends, float erosion and forecast drift are measured, not remembered.

Model

Power BI model with DAX measures: SPI, BEI, CPLI, float lost, forecast slip, critical and near-critical counts.

Report

Leadership pages first, with drill-down to package and activity, and a cause-effect trail ready for EOT.

Sample measures (DAX) 
-- Days between baseline finish and current forecast finish
Forecast Slip (d) =
VAR _fc = MAX ( Snapshot[ForecastFinish] )
VAR _bl = MAX ( Baseline[BaselineFinish] )
RETURN DATEDIFF ( _bl, _fc, DAY )

-- Total float consumed over the last three monthly updates
Float Lost 3U (d) =
VAR _now  = [Total Float (d)]
VAR _prev = CALCULATE ( [Total Float (d)], DATEADD ( 'Update'[DataDate], -3, MONTH ) )
RETURN _prev - _now
